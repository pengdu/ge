# 图引擎接口与类设计

> 依据 `12-详细设计.md`。本文定义公开 C ABI、C++ 宿主封装接口与核心运行时类，不包含实现代码。接口骨架在本文评审后再创建。

## 1. 设计原则

- **双层 API**：C ABI 是插件与跨语言的稳定边界；C++ API 是宿主使用的类型安全封装。
- **回调执行**：引擎将输入 Packet 交给 Node 回调；Node 通过 Host API Emit 或 Completion Queue 输出。
- **所有权明确**：跨 C ABI 只传 opaque handle/POD；Buffer retain/release 由 Host API 管理。
- **控制/数据隔离**：Graph、Mutation、资源、插件为控制接口；Packet、Emit、Completion 为数据接口。
- **版本显式**：Topology、Parameter、Plugin ABI、Operation 均有版本或 ID。

## 3. 公共 C ABI 基础接口

### 3.1 标量、状态和生命周期


`message` 与 `detail_json` 在调用返回前有效；宿主需要长期保存时复制。所有函数通过返回 `ge_status` 报告结果，禁止跨 C ABI 抛异常。

### 3.2 Opaque Handle

```c
typedef struct ge_engine_t* ge_engine_handle;
typedef struct ge_session_t* ge_session_handle;
typedef struct ge_operator_t* ge_operator_handle;
typedef struct ge_buffer_t* ge_buffer_handle;
typedef struct ge_completion_sink_t* ge_completion_sink_handle;
typedef struct ge_subscription_t* ge_subscription_handle;
```

规则：

- `ge_engine_handle`、`ge_session_handle` 由 C 宿主 API 创建与销毁。
- `ge_operator_handle` 由插件创建，生命周期由运行时控制；插件仅经 `operator_destroy` 销毁。
- `ge_buffer_handle` 引用计数管理；借用 view 不改变引用计数。
- 任何空 handle 必须返回 `GE_STATUS_INVALID_ARGUMENT`。

### 3.3 Buffer 与 Packet

```c
typedef enum ge_memory_kind {

  ge_struct_header header;
  ge_packet_seq seq;
  int64_t pts_ns;
  int64_t dts_ns;
```

`type_tag` 是内置类型名或透明业务标签。`metadata_json` 仅作为边界传输格式，内部数据面不解析 JSON。

### 4.3 Host API 与创建参数

```c
typedef struct ge_host_api {
  ge_struct_header header;
  ge_status (*buffer_retain)(ge_buffer_handle buffer);
  void (*buffer_release)(ge_buffer_handle buffer);
  ge_status (*buffer_get_view)(ge_buffer_handle buffer, ge_buffer_view* out_view);
  ge_status (*emit)(const struct ge_emit_args* args);
  ge_status (*completion_push)(ge_completion_sink_handle sink,
                                const struct ge_completion_event* event);
  ge_status (*event_publish)(const struct ge_event* event);
  void (*log)(const struct ge_log_record* record);
  /* ABI 1 尾部追加（12 §3.1）：旧 struct_size 的插件不得访问 */
  ge_status (*buffer_alloc)(void* host_context, size_t size,
                            ge_memory_kind memory_kind, int32_t device_id,
                            ge_buffer_handle* out_buffer);
  ge_status (*buffer_wrap)(void* host_context, const ge_buffer_view* view,
                           ge_buffer_release_fn release, void* release_context,
                           ge_buffer_handle* out_buffer);
} ge_host_api;

typedef void (*ge_buffer_release_fn)(void* data, size_t size, void* context);

typedef struct ge_operator_create_args {
  ge_struct_header header;
  const char* operator_key;
  ge_node_id node_id;
  const char* options_json;
  const ge_host_api* host_api;
  void* host_context;
} ge_operator_create_args;
```

`host_context` 仅可在创建、open、process、submit、close 的同步调用期使用；插件不得在异步完成后保存或解引用该指针。

- `buffer_alloc` 从引擎 Buffer 池分配输出 payload（首期仅 `GE_MEMORY_HOST`），返回一个已持有引用的 handle；插件在 `emit` 后须 `buffer_release`（引擎在 emit 时自行 retain）。
- `buffer_wrap` 包裹插件自有内存为引擎 Buffer；最后一个引用释放时调用 `release(data, size, release_context)`。
- 插件通过 `GE_BUILD_FINGERPRINT`（`ge_plugin.h` 由编译器/标准库/OS/架构/ABI major 拼出的编译期字符串）填写 descriptor 与 manifest 的 `build_fingerprint`；与引擎自身指纹不相等即 `PLUGIN_ABI_MISMATCH`（PLG-3）。

### 4.5 同步 Process 回调

```c
typedef struct ge_emit_args {
  ge_struct_header header;
  void* callback_context;
  const char* output_port;
  const ge_packet_view* packet;
} ge_emit_args;

typedef struct ge_process_request {
  ge_struct_header header;
  ge_session_id session_id;
  ge_topology_version topology_version;
  ge_parameter_version parameter_version;
  uint32_t flags;                       /* GE_PROCESS_FLAG_* */
  const ge_packet_view* inputs;
  const char* const* input_ports;
  uint32_t input_count;
  const char* parameter_json;
  void* callback_context;
} ge_process_request;

#define GE_PROCESS_FLAG_FLUSH 0x1u       /* 输入已结束，输出尾数据；input_count == 0 */

#define GE_PACKET_FLAG_KEYFRAME 0x1u
#define GE_PACKET_FLAG_EOS      0x2u
#define GE_PACKET_FLAG_EVENT    0x4u
#define GE_PACKET_FLAG_DROPPED  0x8u     /* ReorderBuffer 超时缺口占位 */

typedef ge_status (*ge_operator_process_fn)(
    ge_operator_handle op, const ge_process_request* request);
```

- `emit` 仅在 `process` 尚未返回时有效。
- Packet payload 如果需在调用结束后保留，插件必须 `buffer_retain`。
- 引擎验证 output_port、type_tag、Contract、callback_context 和版本后才路由。
- Source（无输入端口）报告"数据耗尽"的方式：在 `process` 内 `emit` 一个 `flags` 含 `GE_PACKET_FLAG_EOS`、`payload == NULL` 的 Packet（与 12 §4.4 "EOS 是带 EOS flag 的空 payload Packet" 一致）。引擎据此把该次调用视为 exhausted，并按 12 §4.4 对所有输出端口注入 EOS；非 Source 节点 emit EOS 返回 `GE_STATUS_INVALID_ARGUMENT`。

### 4.6 异步 Submit 与 Completion

```c
typedef struct ge_submit_request {
  ge_struct_header header;
  ge_request_id request_id;
  ge_session_id session_id;
  ge_topology_version topology_version;
  ge_parameter_version parameter_version;
  ge_packet_seq packet_seq;
  const ge_packet_view* inputs;
  const char* const* input_ports;
  uint32_t input_count;
  const char* parameter_json;
  ge_completion_sink_handle completion_sink;
  /* ABI 1 尾部追加（12 §3.1）：batch 分帧，见下文 */
  uint64_t batch_id;
  uint32_t batch_index;
  uint32_t batch_size;
} ge_submit_request;

typedef struct ge_completion_event {
  ge_struct_header header;
  ge_request_id request_id;
  ge_session_id session_id;
  ge_topology_version topology_version;
  ge_parameter_version parameter_version;
  ge_packet_seq packet_seq;
  ge_status status;
  const ge_packet_view* outputs;
  const char* const* output_ports;
  uint32_t output_count;
} ge_completion_event;

typedef ge_status (*ge_operator_submit_fn)(
    ge_operator_handle op, const ge_submit_request* request);
```

插件只允许通过 `completion_push` 投递结果；不得直接调用任何图/Session 方法。异步事件中的 payload 由插件 retain 后交付，Completion Queue 消费完成后 release。

batch 分帧（ASY-5/ASY-6）：Batcher 把同 key 的请求交给插件时，对同一 operator 实例在同一提交线程上连续调用 `submit`，`batch_id` 相同、`batch_index` 取 `0..batch_size-1`，不与其他 batch 交错；插件可在 `batch_index == batch_size - 1` 时才发起一次后端调用，并为每个 `request_id` 各投递一条 completion。未合批的请求 `batch_size == 1`。旧 `struct_size` 的插件不得读取这三个字段。

### 4.7 Plugin 函数表

```c
typedef struct ge_operator_vtable {
  ge_struct_header header;
  ge_plugin_create_operator_fn create;
  ge_operator_open_fn open;
  ge_operator_process_fn process;
  ge_operator_submit_fn submit;   /* 可空：同步 Node */
  ge_operator_close_fn close;
  ge_operator_destroy_fn destroy;
} ge_operator_vtable;
```

每个 `type@version` 的 vtable 由对应 `ge_operator_descriptor` 直接提供；`create` 返回私有 opaque handle。引擎绝不解引用 handle 内存或依赖其布局。

## 7. 内部核心类设计

### 7.1 控制面类

| 类 | 主要职责 | 关键方法 |
|---|---|---|
| `GraphSpecParser` | JSON 与 GraphSpec 双向转换 | `Parse()`、`Serialize()` |
| `GraphValidator` | 拓扑、Port、参数、共享依赖校验 | `Validate()`、`FindSharedDependencies()` |
| `CapabilityNegotiator` | Edge/扇出协商 | `NegotiateEdge()`、`NegotiateFanout()` |
| `ResourceManager` | 资源账本和租约 | `Reserve()`、`Commit()`、`Release()` |
| `MutationCoordinator` | Session Mutation 串行编排 | `Submit()`、`Prepare()`、`Publish()`、`Retire()` |
| `OperationRegistry` | Operation 状态和结果 | `Create()`、`Transition()`、`Get()` |
| `PluginRegistry` | manifest、C ABI、版本、逻辑卸载 | `Load()`、`Retire()`、`Resolve()`、`SnapshotReferences()` |
| `SessionManager` | Session 创建、查找、销毁与全局停止 | `Create()`、`Destroy()`、`Find()`、`StopAll()` |
| `ParameterStore` | 每 Node 参数快照串行更新与下一 Packet 切换 | `Submit()`、`SwitchAtPacketBoundary()`、`Current()` |
| `Watchdog` | Drain 超时、异步超时周期扫描 | `Tick()` |

| 类 | 主要职责 | 关键方法 |
|---|---|---|
| `RuntimeTopology` | 不可变 Node/Edge/Route 快照 | `FindNode()`、`RoutesFor()`、`InputsFor()` |

| `HostApiAdapter` | 插件 Host API 函数表到 Session/Node 上下文的绑定 | `kVtable`、`Bind()`、`Unbind()` |

### 7.3 生命周期依赖关系

```text
Engine
 ├─ PluginRegistry
 ├─ ResourceManager
 ├─ ExecutorPool
 ├─ Scheduler
 ├─ AsyncRuntime
 │    └─ CompletionQueue / Batcher / ReorderBuffer
 ├─ OperationRegistry
 ├─ MetricsRegistry / EventBus / ObserverExecutorPool / AuditLog / Watchdog
 └─ SessionManager
      └─ Session
           ├─ Atomic<RuntimeTopology>
           ├─ MutationCoordinator
           ├─ CompletionSink
           └─ RetiredTopologyList
                └─ NodeRuntime / EdgeChannel / PluginLease / ResourceLease
                     └─ HostApiAdapter / ParameterStore（每 NodeRuntime 一个）
```

销毁顺序：Session 停止并回收 retired topology → SessionManager 移除 Session → AsyncRuntime 停止接收该 Session Completion 并释放 CompletionSink → PluginLease/ResourceLease 归零 → Engine 销毁共享服务。

## 8. 类关系与依赖规则

- `MutationCoordinator` 可依赖 Validator、Negotiator、ResourceManager、PluginRegistry、OperationRegistry；不可依赖 Scheduler 内部队列。
- `Scheduler` 仅依赖 RuntimeTopology、NodeRuntime、ExecutorPool、PacketRouter；不可访问 GraphSpec JSON 或 PluginRegistry 可变状态。
- `PacketRouter` 只读取 RouteTable 和 Edge Contract；不可发起 Mutation。
- 插件经 `HostApiAdapter` 访问 Buffer、Emit、Completion、Event、Log；不能获得 Engine 或 Session 指针。
- `AsyncRuntime` 是唯一把 CompletionQueue 事件转换为数据面输出的组件。

## 10. JSON 文档版本策略

所有 JSON 控制文档（`GraphSpec`、`MutationPatch`、`PluginManifest`、Capability/Operation 查询结果）采用**顶层整数 `schema_version` + 可选 `$id`**：

```json
{
  "kind": "GraphSpec",
  "schema_version": 1,
  "$id": "ge.dev/schema/graph/v1",
  "name": "live_transcode",
  "nodes": [],
  "edges": []
}
```

规则：

1. 每个文档类别独立维护 `schema_version`，首期均为 `1`。
2. 同一 major 仅新增可选字段，既有字段不可删除、改名或改变语义。
3. 未识别字段默认拒绝，除非该文档顶层显式 `allow_unknown_fields=true`；首期生产默认 `false`，防止拼写错误静默失效。
4. `schema_version` 不兼容时返回 `GRAPH_INVALID` 或 `PLUGIN_MANIFEST_INVALID`，错误详情包含期望/收到版本。
5. `$id` 是可选的人类/工具识别符，不参与运行时版本判断；其 major 必须与 `schema_version` 一致。
6. major 升级需由外部控制系统完成 JSON 迁移，引擎不隐式迁移历史 GraphSpec。
