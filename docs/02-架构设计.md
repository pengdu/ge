# 图引擎概要设计

> 权威需求：`00-需求规格说明书.md`。本设计覆盖首期单机、嵌入式 C++/C 图引擎；未决项仅记录在 `11-概要设计-开放问题.md`，不在本文假设结论。

## 1. 设计目标与原则

### 1.1 目标

- 在数据面低开销执行音视频、推理和透明业务数据图。
- 支持 Session 内原子 Mutation：插入/删除/替换 Node、插入/删除连续 Node 链、动态增删分支。
- 支持 Node 能力导出、构图期协商、扇出公共交集与独立背压。
- 支持裸 so + manifest、稳定 C ABI、多版本灰度、默认逻辑卸载。
- 支持异步推理、同卡跨会话合批、Completion Queue 结果分发。

### 1.2 核心原则

| 原则 | 含义 |
|---|---|
| 控制面与数据面分离 | 校验、协商、预热、准入、审计在控制面；Packet 调度和 Edge 收发在数据面。数据面不获取控制面全局锁。 |
| 拓扑快照不可变 | 已发布 `RuntimeTopology` 不修改。Mutation 构建候选快照，预热成功后原子切换。 |
| 局部影响 | 变更仅替换受影响 Node/Edge；未受影响路径继续消费旧/新快照，不暂停。 |
| 显式拓扑 | 引擎不自动插入转换或分支转换。能力不匹配须由调用方显式加入 Convert/Scale/Resample/MemoryCopy。 |
| 插件 C ABI | so 边界只传 C ABI 函数表、opaque handle、POD 结构和 Buffer handle；不跨边界传递 STL、异常或 C++ 对象。 |
| 版本可追溯 | Packet、拓扑、参数、算子版本和异步请求都有版本标识；迟到结果不能进入新拓扑。 |

## 2. 总体架构

```
┌─────────────────────────────────────────────────────────────────────┐
│ 接入层：C++ API / C API / JSON GraphSpec、Patch、Operation 查询      │
├─────────────────────────────────────────────────────────────────────┤
│ 控制面：GraphBuilder · Validator · CapabilityNegotiator ·           │
│         ResourceManager · MutationCoordinator · PluginRegistry      │
│         Event/Audit/Operation 服务                                  │
├─────────────────────────────────────────────────────────────────────┤
│ 运行时：Engine · Session · RuntimeTopology · Scheduler · Executor   │
│         AsyncRuntime(CompletionQueue/Batcher/ReorderBuffer)         │
├─────────────────────────────────────────────────────────────────────┤
│ 数据面：NodeRuntime · EdgeChannel · Packet · Buffer · MemoryPool    │
│         DataPlaneEvent                                               │
├─────────────────────────────────────────────────────────────────────┤
│ 扩展层：Builtin Operators · so Plugin Adapter · CUDA/TRT/ORT 后端   │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.1 模块边界

| 模块 | 职责 | 不负责 |
|---|---|---|
| `GraphSpec` | JSON 图、patch、模板的纯数据表示 | Node 实例、线程、GPU 资源 |
| `Validator` | 拓扑、端口、参数、引用、反馈环校验 | 运行时媒体格式变化处理 |
| `CapabilityNegotiator` | 计算 ConnectionContract、扇出公共交集、确定性选择与错误诊断 | 插入转换 Node、运行中重新协商 |
| `ResourceManager` | 资源估算、准入、租约、归还和水位 | 抢占、优先级、自动降级 |
| `MutationCoordinator` | 每 Session 串行 Mutation、候选版本构建、预热、发布、收尾 | 跨 Session 原子事务 |
| `PluginRegistry` | manifest 校验、C ABI 适配、type@version、引用和逻辑卸载 | so 内部业务实现 |
| `Scheduler/Executor` | 数据驱动 CPU/GPU 执行 | JSON 解析、能力协商、控制面锁 |
| `AsyncRuntime` | Completion Queue、Batcher、拓扑/参数版本校验、保序 | so 自建工作线程 |
| `Event/Audit` | 数据面事件、旁路观察、指标、审计 | 阻塞或确认数据面事件 |

## 3. 核心数据模型

### 3.1 静态图与运行时图

```text
GraphSpec
  ├─ NodeSpec[]          type@version、name、options、executor
  ├─ EdgeSpec[]          from/to、queue、backpressure、sync
  ├─ TemplateArgs
  └─ GraphOptions

RuntimeTopology (immutable, topology_version)
  ├─ NodeRuntime[]       已 Open 的 Node 实例、参数快照、资源租约
  ├─ EdgeChannel[]       独立队列、ConnectionContract、Edge 状态
  ├─ RouteTable          Port → 下游 Edge 列表（扇出）
  ├─ InputBindingTable   Node → 多输入同步绑定
  ├─ PluginLease[] / ResourceLease[]   对 Plugin/Resource 的引用（合称 TopologyLease）
  └─ TopologyVersion
```

`GraphSpec` 用于控制面比较、导出和 patch；`RuntimeTopology` 是数据面只读执行对象。Session 持有原子 `current_topology` 指针，并维护旧拓扑的延迟回收列表。

### 3.2 Packet 与 Buffer

```text
Packet
  ├─ seq / pts / dts / flags
  ├─ metadata
  ├─ payload: BufferRef
  ├─ topology_version
  └─ parameter_version (可选)

Buffer
  ├─ address / size / memory_kind / device_id
  ├─ ref_count / deleter
  └─ optional custom hooks
```

- 内置媒体/Tensor 类型的格式信息受 ConnectionContract 约束。
- 透明自定义数据使用业务类型标签；引擎不读取其 payload 内部。
- 扇出只增加 `BufferRef` 引用计数；每条 Edge 独立排队与丢弃。

### 3.3 CapabilityDescriptor 与 ConnectionContract

```text
CapabilityDescriptor
  ├─ OperatorIdentity(type@version)
  ├─ FunctionalMetadata
  ├─ PortCapability[]
  │    ├─ direction / cardinality / dynamic_ports
  │    ├─ logical_type_tag
  │    ├─ media_or_tensor_constraints
  │    └─ memory/device/sync constraints
  ├─ ParameterSchema
  ├─ RuntimeCapabilities
  └─ ResourceEstimate

ConnectionContract
  ├─ logical_type
  ├─ selected_media_or_tensor_format
  ├─ memory_kind / device_id
  ├─ sync_policy
  └─ capability_versions
```

协商仅发生在 Build、Create、Validate 与 Mutation 阶段。运行期分辨率变化使用事件机制，不改写 Contract。

## 4. 数据面执行设计

### 4.1 Edge 与扇出

- `EdgeChannel` 是有界单向通道，拥有独立容量、背压和丢弃策略。
- 输出 Port 对应不可变 `RouteTable`，发送 Packet 时遍历下游 Edge，零拷贝分发 payload。
- 每条 Edge 负责自身满队列行为：`block`、`drop_oldest`、`drop_newest`。
- 慢下游只影响本 Edge 的消费或上游背压状态，不篡改其他 Edge 已接收 Packet。
- 扇出共享输出格式必须由协商公共交集确定；不同格式显式建 `Tee + Convert`。

### 4.2 调度

1. 上游 Node 向 Edge 写入 Packet。
2. Edge 根据目标输入 Port 的同步条件尝试标记 Node ready。
3. Scheduler 把 ready Node 提交到对应 CPU/GPU Executor。
4. 同步 Node 调用 `Process`；异步 Node 调用 `Submit` 后释放执行线程。
5. Node Emit 新 Packet 或数据面事件，触发下游。

多输入 Node 按 Contract 选择 `aligned`、`latest` 或 `any`。无状态 Node 可配置并行度；状态 Node 默认单实例串行。

### 4.3 异步推理与 Completion Queue

```
Node Submit
  → Batcher(type@version, model, device_id, parameter_version)
  → Plugin C ABI submit(batch)
  → backend completion
  → CompletionQueue.push(event)
  → AsyncRuntime 校验 session/topology/parameter version
  → ReorderBuffer
  → Edge emit 或丢弃并计数
```

- Batcher 仅同 `device_id` 聚合；最大 batch 与默认 10ms 超时共同限制。
- so 禁止自建工作线程和直接调用图回调；后端完成只投递 Completion Queue。
- Completion 事件带 session、拓扑版本、参数版本、序号、结果/错误。
- 当前拓扑或会话失效时，事件丢弃并计数；不会注入新图。
- Reorder 超时可放行序号缺口，必须显式打 `dropped/timeout` 标记。

### 4.4 数据面事件

- `MediaFormatChanged` 绑定触发新格式的关键帧，并在该帧前沿受影响下游传递。
- 下游 Node 根据能力声明处理、拒绝、报告需要重建或失败。
- EOS、错误、重连、卡顿等状态事件按定义传播。
- 上游控制事件仅 P1，按目标路径上行。
- 观察事件由旁路队列复制给订阅者；慢消费者或投递失败不影响数据面。

## 5. 控制面与 Mutation

### 5.1 统一 Mutation 状态机

```text
Accepted → Building → Validating → Negotiating → Reserving → Warming
         → Publishing → Draining → Succeeded
                        ↘ Failed (Publishing 前失败：旧图不变)
```

- 同一 Session 的 Mutation 串行，可在未开始构建前合并。
- 控制 API 同步返回受理、校验失败或 operation ID；预热、Drain、逻辑卸载等通过 operation 查询最终状态。
- 每次 Mutation 生成候选 GraphSpec 与候选 RuntimeTopology；只有 Publishing 才更新 Session 的原子指针。

### 5.2 插入一个或连续 Node 链

输入：既有 Edge `(U.out → D.in)` 与有序 Node 链 `[N1...Nk]`。

候选变换：

```text
旧：U.out ────────────────→ D.in
新：U.out → N1 → ... → Nk → D.in
```

步骤：

1. 移除候选图中的原 Edge。
2. 加入 Node 链与 `k+1` 条候选 Edge。
3. 对每条新 Edge 协商 Contract；任一失败则拒绝。
4. 准入并 Open/预热所有新 Node。
5. 发布新拓扑；旧 Edge 只服务已入队 Packet 后回收。

该操作作为一个 Mutation 原子生效，数据面不会看到半插入状态。

### 5.3 删除 Node、连续 Node 链与自动 bypass

删除模式：

- **断开删除**：移除目标 Node/链及关联 Edge；调用方显式补连上下游。
- **自动 bypass**：仅适用于目标 Node 或 Node 链的首尾各有唯一外部输入/输出，且中间链为线性专属路径。

```text
旧：U.out → N1 → ... → Nk → D.in
新：U.out ─────────────────→ D.in
```

自动 bypass 的候选新 Edge 必须重新进行能力协商、资源校验和图校验。若无公共能力集、存在额外外部端口、链内含共享 Node/Edge，Mutation 被拒绝并返回依赖或冲突详情。

发布后：

- 新 Packet 直接进入 bypass Edge 或按断开后的新图路由；
- 旧 Node 链以 `Drain` 或 `Fast` 收尾；
- 异步在途结果须携带旧 topology_version，只可进入旧链的收尾范围，不能写入新 Edge；
- 引用归零后 Close Node、释放 Edge、资源及插件引用。

### 5.4 替换 Node

```text
旧：U → OldNode(type@v1, params) → D
新：U → NewNode(type@v2, migrated_params) → D
```

1. 查询新 Node CapabilityDescriptor。
2. 按端口名/显式映射继承旧连接；检查所有 Contract 是否仍成立。
3. 迁移可迁移参数；不可迁移参数必须由调用方提供或 Mutation 拒绝。
4. 预热 NewNode，申请资源。
5. 原子发布新拓扑；OldNode 按 Drain/Fast 收尾。

该机制同时支撑模型升级、算子版本灰度与 so 一键联动替换。

### 5.5 删除分支

分支删除以入口 Edge 或显式 Node 集合定位候选子图：

- 仅删除目标分支独占的 Node 和 Edge；
- 共享 Node/Edge 不被隐式删除；发现共享依赖时返回依赖图并拒绝；
- 公共上游 RouteTable 在发布后移除该分支 Edge，其他分支持续执行；
- 被删分支采用 Drain 或 Fast 收尾，资源归还共享池。

### 5.6 参数热更新

参数更新不重建 RuntimeTopology：

1. 在 Node 的串行参数队列中校验完整新参数集。
2. 构建不可变 `ParameterSnapshot(version+1)`。
3. 在下一个输入 Packet 边界原子切换该 Node 的参数快照。
4. 已入队/在途同步或异步请求继续绑定旧快照。

影响模型执行语义的参数版本是 Batcher 聚合键的一部分。

## 6. 插件设计

### 6.1 交付与加载

首期交付：裸 `.so` + manifest。宿主负责安装、锁定依赖；manifest 描述：

- C ABI major/minor；
- so 标识、构建指纹、依赖版本；
- 算子 type@version、CapabilityDescriptor、资源估算；
- 可选资源路径、最大推理时长。

PluginRegistry 按白名单目录和显式 API 加载，先读取 manifest，再解析 C ABI 导出符号和函数表。任一 ABI、依赖或符号校验失败则拒绝注册。

### 6.2 稳定 C ABI

```text
plugin_get_descriptor(abi_version) -> PluginDescriptor*
plugin_create_operator(type_version, config_json, host_api) -> OperatorHandle
operator_open(handle, context) -> Status
operator_process(handle, input, output_sink) -> Status
operator_submit(handle, request, completion_sink) -> Status
operator_close(handle) -> Status
operator_destroy(handle)
```

实际函数签名以 SDK 定义为准。约束：

- 同 major ABI 仅追加结构字段/函数，不删除或改变既有语义；
- 所有结构体携带 `struct_size`；引擎与插件按共同字段范围访问；
- `host_api` 提供 Buffer、日志、Completion Queue、事件、资源统计等 C ABI 服务；
- 不跨边界抛异常、分配后由另一侧释放 C++ 对象，或传递 STL/RTTI。

### 6.3 版本与卸载

- 注册键为 `type@version`，多版本可共存。
- 默认采用逻辑卸载：停止新引用、移除注册表项、释放可释放资源、保留动态库句柄。
- 物理 `dlclose` 仅显式调用且插件引用、Node、在途请求、定时器、线程和跨边界对象均归零时尝试。
- 一键联动替换：对所有引用旧版本的 Session 逐个执行 Node 替换 Mutation，聚合结果；全成功后逻辑卸载旧版。无跨 Session 原子回滚。

## 7. 资源、故障和观测

### 7.1 资源管理

ResourceManager 维护 CPU、主存、GPU、NVDEC/NVENC、队列 Buffer 的共享池水位。

- Create/Mutation 在预热前申请估算租约；预热报告实际占用后可调整租约。
- 资源不足拒绝新请求，不影响运行 Session。
- Node/分支/Session/插件收尾后归还资源，并发资源释放事件。

### 7.2 故障处理

- Node 错误进入会话级策略：按配置重试/重建；超阈值停止该 Session。
- Session 故障不影响其他 Session。
- 进程崩溃由外部拉起；外部以保存 GraphSpec 全量重建。
- 观察、审计、指标输出均必须旁路化，故障不能阻断数据面。

### 7.3 可观测性

- 指标：Node 吞吐/P50/P99、Edge 队列/丢弃/背压、图延迟、资源水位、Batch 大小/等待/在途、Mutation 和插件操作状态。
- 结构化审计：caller_id、request_id、操作、目标、版本、结果和脱敏摘要。
- 运行时查询：GraphSpec、RuntimeTopology 摘要、Node 状态、参数/能力版本、ConnectionContract、事件和 operation 状态。

## 8. 关键不变量

1. 已发布 RuntimeTopology 不修改；所有拓扑变化经候选版本原子发布。
2. 数据面不获取控制面全局锁，不解析 JSON，不执行能力协商。
3. 一个 Packet 在处理周期内绑定唯一 topology_version 和 parameter_version。
4. 未受影响分支不因 Mutation、事件观察或审计暂停、丢帧或重排。
5. 插件 so 只经稳定 C ABI 交互；默认逻辑卸载，不把 `dlclose` 作为常规升级路径。
6. 扇出每 Edge 独立队列与背压；共享 payload 仅通过引用计数共享。
7. 所有异步完成先经 Completion Queue，再校验版本后交付。
8. 自动 bypass 只适用于线性、专属、单外部输入/输出的 Node 或 Node 链。
