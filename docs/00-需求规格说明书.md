## 1. 产品定义

### 1.1 目标

构建一个可嵌入宿主进程的单机图执行引擎，用于音视频处理、深度学习推理以及业务自定义数据处理。业务方可通过 C++ API 或 C API、以 JSON 图定义构建和运行处理图，并可在不中断未受影响数据路径的前提下，动态调整图拓扑、Node 参数、转码档位、合成成员与算子版本。

首期重点保障：

- 实时音视频处理与推理流水线的低延迟、高性能执行；
- 单机数据中心 GPU（T4/A10/L4 级）上的几十路会话；
- 动态增删转码分支、4–16 路视频合成、异步推理与同卡跨会话合批；
- 独立 so 算子的加载、灰度升级及安全卸载；
- Node 能力导出、上下游能力协商与扇出。

### 1.2 首期范围

| 维度 | 已确认范围 |
|---|---|
| 部署 | 单进程、单机、嵌入式库 |
| 硬件 | 数据中心 GPU：NVIDIA T4/A10/L4 级；CUDA 11+、TensorRT 8+。**修订（OD-06）**：首期 GPU 仅承担推理；编解码、缩放、合成在 CPU（目标机 128 核，单机 ≤20 路编码）。涉及 NVDEC/NVENC 的条目（RES-2、SC-6、§4.2 GPU 占用）按 OD-06 降为 P2 |
| 会话规模 | 几十路会话；单合成图 4–16 路输入 |
| 控制接口 | C++ API、稳定 C API |
| 图定义与 patch | JSON；由外部控制系统提交 |
| 状态恢复 | 外部控制/信令系统保存状态，进程重启后外部全量重建 |
| 认证 | 宿主鉴权；引擎接收 caller_id/request_id 并审计 |
| 引擎升级 | 引擎二进制停止/重启升级；算子 so 支持运行中热升级 |

### 1.3 明确不在首期

- 分布式跨机图、跨进程边；
- gRPC、REST、Python SDK、本地配置文件监听；
- 引擎内置认证、RBAC、守护子进程、引擎二进制热升级；
- 租户配额、优先级、资源抢占、自动降级；
- 消费级 GPU 的兼容与性能承诺；
- HLS 排空收尾；
- AI/设备运行期事件；
- 音频完整处理链路（采样率统一、声道布局、AGC、AEC）；
- 不可信算子的进程级沙箱；
- 自动插入格式转换或自动生成不同格式扇出分支。

## 2. 术语

| 术语 | 说明 |
|---|---|
| Graph | 由 Node、Port、Edge 组成的处理拓扑 |
| Node / Operator | 数据处理单元，例如解码、缩放、推理、混合、编码 |
| Port | Node 的输入或输出插槽 |
| Edge | 两个 Port 间的有界数据通道，具有队列、背压和同步属性 |
| Packet | 在 Edge 上流动的数据封装，含序号、PTS/DTS、元数据、payload |
| Session | 一个 Graph 的运行实例 |
| GraphSpec | 图的 JSON 中间表示；配置/API 最终都落为该表示 |
| Mutation | 对运行中图的事务性变更 |
| ConnectionContract | 构图/变更期协商后冻结的边数据契约 |
| CapabilityDescriptor | Node 导出的机器可读能力与功能描述 |
| Rendition | 同一输入源派生出的一个转码输出档位 |
| Completion Queue | 推理算子 so 投递异步完成事件、引擎消费并分发的队列 |

## 3. 总体功能需求

### 3.1 图模型与生命周期

| ID | 需求 | 优先级 |
|---|---|---|
| GM-1 | 支持有向图、多入多出 Node、扇入和扇出；反馈环必须显式声明，首期为 P1。 | P0 |
| GM-2 | 支持 Source、Sink、Transform、Mux、Demux、Tee、Switch、RateLimiter、Delay 等基础 Node 类别。 | P0 |
| GM-3 | 支持图模板及参数实例化；同一模板可创建多个 Session。 | P0 |
| GM-4 | Graph 生命周期：Build → Validate → Initialize → Start → Running → Pause/Resume → Stop → Destroy。 | P0 |
| GM-5 | Node 生命周期：Open、同步 Process 或异步 Submit、Close；支持资源预热。 | P0 |
| GM-6 | 支持 EOS 沿图传播；Sink 收齐数据后关闭。支持 Flush 清空待处理队列。 | P0 |
| GM-7 | 同一进程内多个 Session 相互隔离；一个 Session 的停止、失败或资源不足不影响其他 Session。 | P0 |

### 3.2 构图、校验与控制面

| ID | 需求 | 优先级 |
|---|---|---|
| CTL-1 | 提供等价 C++ API 与稳定 C API，用于图创建、校验、运行、停止、销毁、查询、Mutation、参数更新、事件订阅和 so 管理。 | P0 |
| CTL-2 | C API 不暴露 C++ STL、异常、RTTI 或 C++ 对象所有权；采用显式句柄、长度、错误码和 JSON Buffer。 | P0 |
| CTL-3 | 图定义、变更 patch、复杂参数使用 JSON；外部控制系统负责读取、审核和提交，引擎不监听本地文件变化。 | P0 |
| CTL-4 | Build/Create 前执行 JSON Schema、图拓扑、Node/Port、参数、能力协商、资源准入检查；失败返回结构化诊断。 | P0 |
| CTL-5 | 操作同步返回 accepted/rejected、校验结果、当前图/参数版本及 operation ID（若有后置异步阶段）。 | P0 |
| CTL-6 | 预热、排空删除、so 卸载等长操作必须支持 operation ID 查询与最终状态订阅，状态含 accepted/running/succeeded/failed/cancelled。 | P0 |
| CTL-7 | 图定义与 API 构图都必须收敛为同一 GraphSpec；当前生效图、边契约与参数可导出 JSON 复现。 | P0 |

### 3.3 Packet、内存与透明自定义数据

| ID | 需求 | 优先级 |
|---|---|---|
| DT-1 | Packet 含图内单调序号、PTS/DTS、Flags、元数据、引用计数 payload。 | P0 |
| DT-2 | 内置类型支持 VideoFrame、AudioFrame、Tensor、Bytes、JSON/Struct，并支持 Host、Pinned、Device、DMA-BUF 内存抽象。 | P0 |
| DT-3 | 同一 payload 可零拷贝共享；扇出不复制数据，支持可选 COW。 | P0 |
| DT-4 | 提供分级主存/显存 Buffer Pool，避免热路径频繁 malloc/cudaMalloc。 | P0 |
| DT-5 | 支持透明自定义数据：TXT、任意 bytes、任意 C++ 对象/结构体均可作为 payload；引擎只承载 payload、业务逻辑类型标签和元数据。 | P0 |
| DT-6 | 透明自定义数据不要求向框架注册结构体、Schema 或序列化格式；引擎不解析、序列化、校验内部字段。两端 Node 负责内存所有权与业务语义。 | P0 |
| DT-7 | 自定义数据在纯进程内传递不强制序列化；跨设备、深拷贝、落盘等场景可选提供序列化、复制和析构钩子。 | P1 |
| DT-8 | P1 支持与 AVFrame、OpenCV Mat、Torch Tensor、DLPack 的零拷贝互转。 | P1 |

### 3.4 Node 能力导出与协商

| ID | 需求 | 优先级 |
|---|---|---|
| CAP-1 | 每个 Node/算子导出 CapabilityDescriptor，并可通过 C++/C API 查询，随 so 元数据注册。 | P0 |
| CAP-2 | 能力描述包含：端口契约、媒体/Tensor 格式、执行与资源能力、功能元数据。 | P0 |
| CAP-3 | 端口契约包含端口名、方向、必需性、基数、是否支持动态增减、逻辑数据类型标签、同步语义。 | P0 |
| CAP-4 | 媒体能力包含视频像素格式、尺寸、帧率、色彩空间、HDR；音频格式、采样率、声道；Tensor dtype/shape/layout。 | P0 |
| CAP-5 | 执行能力包含设备、可接受/输出内存类型、零拷贝能力、最大并行度和资源估算。 | P0 |
| CAP-6 | 功能元数据包含 type@version、人可读功能说明、标签、参数 Schema、状态性、同步/异步、热更新能力及支持的运行期事件。 | P0 |
| CAP-7 | 透明自定义数据仅按业务逻辑类型标签精确相等匹配；引擎不根据 payload 推导兼容性。 | P0 |
| CAP-8 | 引擎只在 Build、Validate、Create 和 Mutation 提交前协商。运行期格式变化不重新协商。 | P0 |
| CAP-9 | 每条 Edge 协商生成不可变 ConnectionContract：逻辑类型、格式、内存/设备、同步语义及能力版本。 | P0 |
| CAP-10 | 双端无共同能力集合时拒绝构图/变更，返回冲突维度、双方候选集合和建议的显式转换类型。禁止隐式插入转换 Node。 | P0 |
| CAP-11 | 多可行解时，必须按确定性优先规则选择；相同输入必须生成字节等价的 ConnectionContract。 | P0 |

### 3.5 扇出

| ID | 需求 | 优先级 |
|---|---|---|
| FAN-1 | 一个输出 Port 可连接一个或多个下游输入 Port。 | P0 |
| FAN-2 | 上游共享输出契约必须是所有下游可接受能力集合的公共交集。 | P0 |
| FAN-3 | 公共交集为空时拒绝整个构图/变更；不同格式分支必须由调用方显式建模为 Tee + Convert/Scale/Resample/MemoryCopy。 | P0 |
| FAN-4 | 同一输出 Packet 可零拷贝分发；每条扇出 Edge 都有独立队列、背压策略和消费进度。慢下游不得修改其他下游已接收 Packet。 | P0 |
| FAN-5 | 运行中可通过 Mutation 增删扇出下游；新增下游触发受影响端口的增量协商，若破坏既有公共契约则拒绝变更。 | P0 |
| FAN-6 | 每条扇出 Edge 可分别配置队列容量、阻塞/丢弃最旧/丢弃最新策略；扇出整体背压聚合规则可配置并可观测。 | P1 |

### 3.6 调度、同步、背压与 GPU

| ID | 需求 | 优先级 |
|---|---|---|
| SC-1 | 数据驱动调度：输入满足条件时调度 Node，无轮询空转。 | P0 |
| SC-2 | 支持 CPU、GPU 执行器；会话共享全局资源池，Node 可声明设备和并行能力。 | P0 |
| SC-3 | 无状态 Node 可并行处理多个 Packet；输出按序交付，异步乱序完成采用 reorder 缓冲。 | P0 |
| SC-4 | 多输入 Node 支持 aligned、latest、any 同步策略。 | P0 |
| SC-5 | 下游拥塞经有界 Edge 传播背压；Source 可据此降帧。 | P0 |
| SC-6 | GPU 流水线支持 CUDA Stream 异步与 Device Buffer 零拷贝，避免不必要 D2H/H2D。 | P0 |
| SC-7 | 首期不提供会话优先级、资源抢占或自动降级。 | P0 |

### 3.7 运行中图变更

| ID | 需求 | 优先级 |
|---|---|---|
| MUT-1 | 支持运行中插入 Node、删除 Node、替换 Node、增删 Edge、增删扇出/扇入分支。 | P0 |
| MUT-1a | 支持在一条既有 Edge 的上游/下游 Port 间**插入一个或多个连续 Node**：候选拓扑将原 Edge 拆为“上游→新 Node 链→下游”的连续 Edge；Node 链内每个 Node 必须已预热，且全部新 Edge 的能力协商、资源准入、参数校验成功，否则 Mutation 整体拒绝。插入链作为一个事务原子生效，运行中不可见半插入状态。 | P0 |
| MUT-1b | 支持**替换 Node**：以指定 type@version 的新 Node 继承旧 Node 的端口连接与可迁移参数；新旧端口契约、能力协商及资源准入必须通过。新 Node 预热后原子切换，旧 Node 按 Drain/Fast 策略收尾。不可迁移参数、端口不兼容或预热失败时整体拒绝，旧 Node 保持运行。 | P0 |
| MUT-1c | 支持**删除分支或连续 Node 链**：从分支入口 Edge 或链首 Node 起，删除所选子图内 Node 与专属 Edge；删除连续链时可选择断开上下游或在链首/链尾均为唯一单入单出时自动 bypass 连接。公共上游和其他分支必须继续运行。分支/链内共享 Node 或 Edge 不得被隐式删除；发现共享依赖时拒绝并返回依赖清单，调用方须显式指定删除范围或先重构。 | P0 |
| MUT-2 | 一批拓扑变更以事务提交；校验、能力协商、资源准入、预热任一步失败，图保持旧状态。 | P0 |
| MUT-3 | 成功提交后，未受影响路径无丢帧、无额外暂停；受影响局部路径暂停有界，目标不超过一个帧周期。 | P0 |
| MUT-4 | 同一 Session 内变更请求按队列串行并可合并；跨 Session 相互独立。 | P0 |
| MUT-5 | 删除 Node/分支支持 Drain 与 Fast 两种策略；Drain 排空，Fast 立即丢弃待处理数据。 | P0 |
| MUT-6 | 支持删除**单输入、单输出**中间 Node 时的自动旁路（bypass）：引擎移除该 Node 及关联 Edge，并自动尝试连接其唯一上游与唯一下游 Port。旁路后的能力协商、资源准入和图校验必须成功，否则整个 Mutation 拒绝且保持旧图。多输入、多输出 Node 必须由调用方显式重连。 | P0 |
| MUT-7 | 图变更前支持 dry-run；变更后可导出完整 GraphSpec 和协商契约。 | P1 |
| MUT-8 | 跨 Session 原子事务不在首期。 | P0 |

### 3.8 Node 参数热更新

| ID | 需求 | 优先级 |
|---|---|---|
| PAR-1 | Node 在元数据中声明参数 Schema、默认值、类型、范围/枚举、组合约束和热更新能力。 | P0 |
| PAR-2 | 一次请求只修改同一 Node；多个参数作为 Node 内原子事务。 | P0 |
| PAR-3 | 热更新从该 Node 下一个输入 Packet 生效；已入队、执行中及异步在途请求继续使用旧参数。 | P0 |
| PAR-4 | 每个 Packet 的完整处理周期绑定唯一 parameter_version；输出可带该版本。 | P0 |
| PAR-5 | 同一 Node 参数更新按提交顺序串行；不同 Node 可并行。 | P0 |
| PAR-6 | 不支持原地热更新的参数（模型路径、codec、端口、设备等）必须拒绝，不得隐式重建 Node；可提示调用方使用 Mutation。 | P0 |
| PAR-7 | 参数校验或底层应用失败时整体失败并保留旧参数；返回结构化错误和当前版本。 | P0 |
| PAR-8 | 参数变更历史可按来源、时间、版本和生效 Packet 查询。 | P1 |

### 3.9 异步推理与跨会话合批

| ID | 需求 | 优先级 |
|---|---|---|
| ASY-1 | 推理/加速器 so 支持 Submit(request) → handle 的非阻塞异步契约。 | P0 |
| ASY-2 | 算子 so 禁止创建/持有工作线程；不得直接调用图回调。 | P0 |
| ASY-3 | so 将完成事件投递至引擎 Completion Queue；引擎专用上下文消费、校验并分发。事件含句柄、序号、结果/错误、拓扑版本。 | P0 |
| ASY-4 | 完成结果保序交付；reorder 超时允许产生序号缺口，但缺失请求必须带 dropped/timeout 元数据，禁止静默丢失。 | P0 |
| ASY-5 | 同 type@version、模型配置、device_id 的跨会话请求可合批；仅同卡合批，禁止跨 GPU 聚合。 | P0 |
| ASY-6 | batch 受最大 batch 和超时双约束；默认超时 10ms，可按 Node/模型配置；凑批期间不占 Executor 线程。 | P0 |
| ASY-7 | 支持会话、Node、全局关闭合批；关闭合批的实时会话应保持单路延迟。 | P0 |
| ASY-8 | 影响模型执行语义的不同 parameter_version 不得混入同一 batch。 | P0 |
| ASY-9 | 首期不提供取消在途推理；Stop/Flush/变更等待在途完成，超时后丢弃结果且不得注入新图。模型元数据必须声明最大推理时长。 | P0 |
| ASY-10 | 图变更、模型/so 升级后，旧拓扑的迟到结果不得注入新拓扑。 | P0 |

| ID | 需求 | 优先级 |
|---|---|---|
| PLG-1 | 算子以独立 so 加载；仅从配置白名单目录通过显式 API 加载。 | P0 |
| PLG-2 | so 必须提供元数据：算子清单与能力、ABI 版本、依赖、构建指纹。 | P0 |
| PLG-3 | so 与引擎必须同编译器、标准库和关键编译选项构建；ABI/依赖/符号任一不匹配则拒绝。 | P0 |
| PLG-4 | 同 type@version 只能有一个注册来源；不同版本可共存，图和 Mutation 可显式指定版本。 | P0 |
| PLG-5 | so 可在运行中加载，并可用于新图和 Mutation；支持加载新版、灰度会话切换、收尾旧版的热升级。 | P0 |
| PLG-6 | so 卸载前必须停止新引用并确认运行图引用、在途异步请求、线程、定时器、跨 so 对象均归零。仍被引用不得强制 dlclose。 | P0 |
| PLG-7 | 无法证明安全 dlclose 时允许逻辑卸载：从注册表移除并释放可释放资源，保留句柄并上报降级。 | P1 |
| PLG-8 | so 加载、注册、版本引用、卸载全过程必须审计；可查询任一会话使用的 so/算子版本。 | P0 |
| PLG-9 | 提供 SDK 头文件、CMake 脚手架、元数据打包工具、ABI CI 对拍及 dry-run 加载检查工具。 | P0 |

### 3.11 运行期事件

| ID | 需求 | 优先级 |
|---|---|---|
| EVT-1 | 事件含事件 ID、类别、类型、图/会话/源 Node、时间、关联 Packet 序号/PTS、严重级别和结构化详情。 | P0 |
| EVT-2 | 区分数据面事件和观察事件：观察事件是不可阻塞的旁路副本，上层仅观察，不能确认、拒绝或阻塞。 | P0 |
| EVT-3 | 首期媒体格式事件包括分辨率、像素格式、帧率、色彩空间、HDR、codec 参数变化。 | P0 |
| EVT-4 | MediaFormatChanged 必须绑定触发新格式的关键帧；格式事件先于该关键帧到达受影响下游。 | P0 |
| EVT-5 | 下游 Node 声明格式变化能力，并响应已处理、不支持、需要重建或失败；引擎记录告警和受影响路径，但不等待上层决定。 | P0 |

## 4. 核心业务场景

### 4.1 动态增删转码档位

输入公共解码路径可在运行中增删 `Scale → Encode → Mux → Sink` 输出分支。

- 事件驱动触发（CDN 回执、带宽策略），同 Session 内请求串行合并；
- 新档位从当前帧开始，首帧 IDR，音画同步偏差 ≤40ms；
- 新增/删除不得影响既有档位：零丢帧、无花屏、无额外空档；
- 删除支持 Drain 和 Fast；Drain 默认超时 2s 后降级 Fast；FLV 和 MP4 排空完整性必须可验；
- codec 切换 H.264↔H.265 不可播窗口 ≤500ms；
- 单次拓扑生效 <100ms（不含编码器初始化/CDN 建连）；新增档位首帧 <1s + 外部初始化耗时；
- 每会话每分钟一次增删，持续 24h 无死锁、无句柄/显存泄漏。

### 4.2 4–16 路会议视频合成

多路成员输入经严格时间对齐后合成一路输出。

- 成员加入/退出是图变更事务；成员首帧直接出现，无过渡动画；
- 以可配置基准时钟对齐；窗口 20–100ms 可配；超时策略支持冻结帧、黑帧、占位图或跳过；冻结超过可配阈值（默认 10s）升级为占位图；
- 支持自动网格、手动位置/尺寸/z-order/cover/contain、布局模板与下一输出帧生效的热调；
- 主讲人选择由上层策略决定，通过布局变更下发；
- 音视频成员可独立进出；混音支持成员静音和增益热更新，但完整音频链路不在首期；
- 加入至首帧 <1s（不含源端/CDN 建连），布局热调 ≤1 帧周期+50ms；
- 16 路 1080p30 合成输出在单张 T4/A10/L4 级 GPU 上完成；合成+编码 GPU 占用 <50%；成员进出每分钟≥10次、24h 无资源增长。

### 4.3 独立 so 热升级与异步推理

- so 支持多版本共存与会话级灰度；so 禁止自建线程；
- 推理异步完成经 Completion Queue 分发，避免回调直接进入图；
- 同卡跨会话动态 batch，默认等待 10ms；实时会话可关闭合批；
- 单卡检测模型 batch≤8 场景，合批后路数较逐路推理提升≥3倍，P99 延迟增幅≤合批超时+1帧；
- 版本切换、Stop、Flush、卸载均不得产生孤儿结果；无 Cancel 时等待在途完成或超时丢弃；
- so 加载<50ms，引用归零后的卸载等待<100ms；升级后24h 不出现因卸载导致的延迟崩溃。
