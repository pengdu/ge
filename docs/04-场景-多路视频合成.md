# 场景需求分析：多路视频合成一路（Mix）

> 依据 `docs/01-需求分析.md`。本文档只做需求分析，不涉及设计。

## 1. 场景背景

连麦 / 会议类业务需要将多路参与者视频合成为一路输出（大画面 + 画中画 / 宫格），典型链路：

```
各参与者拉流 → 多路解码 → (对齐) → 合成 Mix → 编码 → 推流/录制
```

与单路转码的本质差异：**多输入汇聚 + 严格时间对齐 + 成员动态进出 + 布局动态调整**，四个特性叠加使该场景成为引擎中"动态图修改 + 多输入同步"两个需求的高压测试场。

### 1.1 已确认口径

| 问题 | 结论 | 对需求的影响 |
|---|---|---|
| 应用 | **连麦/会议**：参与者上下麦动态加入/退出，输入集合高频变化 | 与"动态增删转码链路"场景叠加：成员变化 = 图结构变化，且发生在多输入汇聚节点上游 |
| 规模 | **4-16 路**，布局为宫格/大窗+小窗类 | 单图单卡范围内；不需分层合成，但 16 路解码并发的资源管理仍是约束 |
| 同步 | **严格时间对齐**：各输入帧按时间戳对齐后合成，某路无帧按策略补偿 | 必须定义对齐窗口、超时行为、迟到帧处理；这是全部需求中语义最严格的一项 |
| 布局 | **自动网格 + 手动指定 + 运行中动态调整** 三种都要 | 布局是可热变更的图参数而非静态配置；布局变化不得中断输出 |

## 2. 与既有需求的关系

本场景不新增引擎级能力类别，是对既有需求的组合高压使用：

| 本场景需要 | 对应 01 文档需求 | 本场景带来的强化 |
|---|---|---|
| 成员动态进出 → 动态增删输入分支 | FR-DM（动态图修改） | 变更对象从"输出侧分支"变为"**输入侧分支**"：删除输入路 = 撤销汇聚节点的一个输入；这要求动态修改支持多输入节点的端口级变更，且变更期间汇聚节点持续运行 |
| 严格对齐 | FR-SC-7（输入同步 aligned 策略） | 从"节点通用策略"强化为"场景核心语义"：需定义对齐窗口、窗口漂移、缺帧补偿策略 |
| 16 路并发解码 | FR-RT-3（多会话/多分支共存） | 单图内 16 条解码分支的资源上限与公平性 |
| 布局热调 | FR-DM-2（参数热更新） | 布局参数结构化程度高（嵌套、数组），超出普通标量参数 Schema |
| 成员进出风暴 | FR-DM + TR-A-8 | 会议场景成员进出可能短时高频（掉线重连），需合并/防抖 |

## 3. 用户故事

- **US-M1** 作为会议系统，当新成员上麦时，我提交"加入合成"请求，从提交到该成员画面出现在合成输出中的时间 < 1 s，期间既有成员画面无任何中断/花屏。
- **US-M2** 作为会议系统，当成员下麦/掉线时，我提交"退出合成"请求，其画面按策略处理（移出布局自动重排 / 保持占位），其余成员画面无中断。
- **US-M3** 作为会议系统，成员掉线但未明确退出时，其画面在等待 T 秒后自动显示占位图（名字+头像），该成员恢复后自动切回真实画面。
- **US-M4** 作为主持人/策略，我要把某成员从小窗切到大窗、调整窗口位置大小、加减字幕水印层，输出全程不中断、不撕裂。
- **US-M5** 作为运营，路数变化（2 人→9 人）时自动宫格重排，重排过程平滑（无黑屏闪烁、可选过渡动画为 P2），各路画面不丢失。
- **US-M6** 作为会议系统，成员网络抖动导致帧迟到/缺失时，合成不能停：按对齐窗口等待，超时用该路上一帧（冻结帧）补偿，窗口与策略可配。
- **US-M7** 作为运维，我要查询当前合成画面的成员清单、每路的实时状态（正常/卡顿/占位中）、当前布局，并导出复现。
- **US-M8** 作为业务方，音频合成（混音）与视频合成独立处理：成员仅关摄像头时其音频仍参与混音，仅静音时其视频仍参与合成。

## 4. 功能需求

### 4.1 成员动态进出（对应图结构变更）

| 编号 | 需求 | 优先级 |
|---|---|---|
| MX-I-1 | 提交"加入合成"：成员标识 + 拉流地址 + 画面角色（宫格成员/主讲/字幕层等）+ 可选初始布局参数 | P0 |
| MX-I-2 | 加入过程一次事务完成：拉流连接 → 解码就绪 → 首帧可用 → 接入合成节点 → 布局更新，任一步失败整体回滚，合成输出不受影响 | P0 |
| MX-I-3 | 新成员画面出现在输出中时，其画面必须是"已就绪"的帧（从其首帧/首 IDR 开始），不得出现半帧/花屏/绿屏；**首帧直接出现，无过渡动画** | P0 |
| MX-I-4 | 提交"退出合成"：移除该路输入 + 从布局移除 + 可选保留占位（见 MX-P-2），其余成员画面不中断 | P0 |
| MX-I-5 | 成员重连（退出后再次加入）复用同一标识，不产生两份画面 | P0 |
| MX-I-6 | 进出风暴合并：同一会议短时间多次进出请求排队/防抖合并执行，接口返回"处理中"不阻塞 | P1 |
| MX-I-7 | 并发上限：同时 16 路输入；超出时拒绝加入并返回明确原因（资源/路数上限） | P0 |

### 4.2 时间对齐与缺帧补偿（场景核心）

| 编号 | 需求 | 优先级 |
|---|---|---|
| MX-S-1 | 合成节点按时间戳窗口对齐各输入：以基准时钟（可配：主讲路/最新到达路/系统时钟）为准 | P0 |
| MX-S-2 | 对齐窗口可配（如 20-100ms）；窗口内到齐立即合成，窗口超时不再等待 | P0 |
| MX-S-3 | 某路窗口超时未到帧时的补偿策略可配：**冻结帧**（用该路上一帧）/ **黑帧** / **占位图**（成员名+头像，常用于 US-M3）/ **跳过该路本次合成**（画面区域空缺）；**冻结帧持续超过可配阈值（默认 10s）自动升级为占位图**（两级补偿） | P0 |
| MX-S-4 | 迟到帧处理可配：丢弃（不追） / 补入下一窗口（允许一窗口相位） | P0 |
| MX-S-5 | 各路帧率不同（30/15fps）时，低帧率路自动复用最近帧，不拖慢合成输出帧率 | P0 |
| MX-S-6 | 基准路自身缺失时可配：冻结输出等待恢复 / 自动切换基准（选最新到达路）；**主讲画面切换由上层策略决定，通过布局变更下发**（复用 MX-L-3） | P1 |
| MX-S-7 | 合成输出帧率与时间戳独立于各输入帧率，由配置决定（如固定 30fps 输出） | P0 |
| MX-S-8 | 对齐窗口内不得因等待造成整体延迟超出窗口上限；窗口即该场景端到端延迟下界，需在指标中体现 | P0 |

### 4.3 布局管理

| 编号 | 需求 | 优先级 |
|---|---|---|
| MX-L-1 | 自动网格布局：按当前成员数自动选择宫格规格（1/2/2+1/4/9 宫格），成员进出触发自动重排 | P0 |
| MX-L-2 | 手动布局：通过 API/配置指定每路的位置、尺寸、层级（z-order）、裁剪/填充模式（cover/contain），支持画中画、主讲大窗+小窗列表 | P0 |
| MX-L-3 | 布局热调整：位置/大小/层级/裁剪模式修改在下一输出帧生效，输出不中断、不撕裂 | P0 |
| MX-L-4 | 手动与自动模式可切换；手动调整某成员后，后续成员进出不破坏该成员的手动位置（其余自动重排） | P1 |
| MX-L-5 | 布局模板：预置/自定义布局模板，一键切换整套布局（如"演讲模式"→"讨论模式"），切换视为一次事务 | P1 |
| MX-L-6 | 非视频层：文字/图片/字幕/水印层可动态增删改（属性：内容、位置、层级、透明度），与成员画面统一参与布局 | P1 |
| MX-L-7 | 重排时可选平滑过渡（画面缩放/位移动画）；无动画时重排必须发生在帧边界，无半重排状态 | P2 |

### 4.4 音频混音（边界：接口对齐但不展开实现）

| 编号 | 需求 | 优先级 |
|---|---|---|
| MX-A-1 | 成员加入/退出时其音频同步加入/退出混音；音视频进出可独立请求 | P0 |
| MX-A-2 | 视频退出（关摄像头）不影响该成员音频；反之亦然（US-M8） | P0 |
| MX-A-3 | 混音节点支持按成员静音/调节增益（参数热更新） | P1 |

### 4.5 操作与状态

| 编号 | 需求 | 优先级 |
|---|---|---|
| MX-O-1 | 成员/布局/混音全部操作程序化 API；操作返回受理结果，异步过程（拉流预热、排空）提供状态查询与完成通知 | P0 |
| MX-O-2 | 任意时刻查询：成员清单及每路状态（连接中/首帧等待/合成中/占位中/退出排空中）、当前布局、对齐窗口当前实际延迟 | P0 |
| MX-O-3 | 当前生效的成员 + 布局 + 混音配置可导出复现 | P1 |

## 5. 非功能需求（本场景专项）

| 编号 | 指标 | 目标 | 备注 |
|---|---|---|---|
| MN-1 | 成员加入：提交 → 该成员首帧出现在输出 | < 1 s（不含 CDN/源端建连耗时，该部分单列状态） | 含拉流+解码+接入合成 |
| MN-2 | 成员加入对既有画面的影响 | 零中断、零花屏、输出帧率不降 | 可逐帧校验 |
| MN-3 | 布局调整生效延迟 | 下一输出帧（≤ 1 帧周期 + 50ms） | |
| MN-4 | 合成新增端到端延迟（对齐窗口 + 处理） | ≤ 对齐窗口 + 2 帧周期 | 窗口是延迟下界（MX-S-8） |
| MN-5 | 单路成员掉线到占位图出现 | ≤ 配置的等待 T（默认可配，如 3s） | |
| MN-6 | 16 路满配合成 1080p30 输出 | 单张数据中心 GPU（T4/A10/L4 级）完成，合成+编码占用 GPU < 50%（为后续 AI 处理留预算） | 消费级卡不承诺 |
| MN-7 | 成员进出风暴 | 每会议每分钟 ≥ 10 次进出，持续 24h 无死锁、无资源泄漏、无画面残留（已退出成员画面不再出现） | |
| MN-8 | 16 路解码+合成+编码显存 | 常驻显存有上限且与进出次数无关（无增长） | 检验输入侧动态变更的回收 |

## 6. 约束与假设

- 单成员画面分辨率上限假定为 1080p（上行限制），合成输出上限 1080p（4K 合成列为 P2）
- 各成员源时间戳来自不同客户端时钟，存在相位差与时钟漂移；本场景的对齐基于引擎内到达的时间戳，不做全局时钟校正（时钟校正属于信令层职责，列为边界外）
- 布局动画（MX-L-7）仅为视觉需求，不影响对齐与帧率语义

## 7. 开放问题（已全部决策）

| # | 问题 | 决策 | 落地 |
|---|---|---|---|
| Q1 | 新成员画面首帧过渡 | **直接出现**，无淡入动画；动画类过渡（淡入/重排动画）统一归入 MX-L-7（P2） | MX-I-3 验收口径确定 |
| Q2 | 目标硬件 | **数据中心 GPU（T4/A10/L4 级）**，MN-6 以单张此类卡为基准；消费级卡不承诺 | MN-6 可测 |
| Q3 | 主讲路掉线处理 | **上层策略决定**：切谁主讲由信令/业务层决策后向引擎下发布局变更（复用 MX-L-3 布局热调）；引擎只保证切换不中断 | MX-S-6 收窄为"引擎可配冻结输出等待恢复"，切换逻辑归上层 |
| Q4 | 引擎重启后成员状态 | **外部重建**：成员状态以信令层为准，引擎重启后由会议系统全量重建；引擎不持久化 | 无持久化需求；引擎需保证重建够快（MN-1） |
| Q5 | 冻结帧时长上限 | **自动升级占位**：冻结持续超过阈值（可配，如 10s）自动升级为占位图（两级补偿） | MX-S-3 新增升级语义 |
| Q6 | 混音范围 | **随合成场景**：作为 MX-A 需求组（P0/P1）不展开细节；采样率统一、声道布局、AGC/回声消除等完整音频链路不在本项目范围，引擎预留混音算子接口 | MX-A 范围冻结 |

### 7.1 决策对正文的修订

- **MX-I-3**（加入）明确：首帧直接出现，无过渡动画
- **MX-S-3** 补充：冻结帧持续超过可配阈值后**自动升级为占位图**
- **MX-S-6** 修订：主讲路掉线时引擎行为可配为"冻结输出等待恢复"或"自动选最新到达路为基准"（基准切换），**主讲画面切换由上层通过布局变更下发**
- **MN-6** 明确以数据中心 GPU（T4/A10/L4 级）为验收基准

## 8. 验收要点（需求级）

- 成员加入：既有成员画面逐帧录制，帧号/时间戳连续无中断；新成员画面首帧完整无花屏
- 掉线补偿：人为停发某路输入，验证冻结帧/占位图按策略出现，恢复后自动切回
- 对齐：各路人为加抖动（0-80ms），输出帧率稳定、各画面相位差不超过窗口、总延迟 ≤ MN-4
- 布局热调：连续调整位置/大小/层级，输出无撕裂、无半重排、生效延迟 ≤ MN-3
- 重连：同一成员断开重连，画面不重复、不残留
- 风暴：MN-7 压测通过；显存/句柄水位与进出次数无关
- 回滚：加入时拉流失败/解码资源不足，既有合成完全无影响
