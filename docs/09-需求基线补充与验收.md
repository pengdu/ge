# 需求基线补充：控制面、资源、可靠性与全局验收

> 本文档补齐 `01-需求分析.md` 与场景文档之外的横切需求。本文档完成后，首期需求基线冻结。

## 1. 已冻结的产品边界

| 维度 | 首期决策 |
|---|---|
| 运行形态 | 单机、嵌入式图引擎；几十路会话规模 |
| 控制入口 | C++ API + C API；不提供 gRPC、REST、Python SDK |
| 图/变更配置格式 | JSON |
| 配置进入方式 | 外部控制系统通过 API 提交；引擎不监听本地文件变更 |
| 操作语义 | 同步返回受理/校验/提交结果；预热、排空等长操作以 operation ID 异步查询或订阅最终结果 |
| 状态恢复 | 图、会话、成员、档位状态由外部控制/信令系统保存；引擎重启后外部全量重建 |
| 引擎升级 | 引擎二进制采用重启升级；独立算子 so 支持运行中加载、版本灰度、卸载 |
| 认证授权 | 宿主负责鉴权；引擎记录调用来源与全量操作审计 |

## 2. 控制面需求

### 2.1 C++ / C API

| 编号 | 需求 | 优先级 |
|---|---|---|
| CTL-1 | 提供等价的 C++ API 与稳定 C API：创建/校验/启动/停止/销毁图，会话查询，动态变更，参数热更新，事件订阅，so 管理 | P0 |
| CTL-2 | C API 不暴露 C++ STL、异常、RTTI 或对象生命周期；所有跨 ABI 数据使用显式句柄、长度与错误码 | P0 |
| CTL-3 | 图定义、patch、复杂参数以 JSON 字符串或 Buffer 传入；引擎返回结构化 JSON 错误详情 | P0 |
| CTL-4 | API 版本化；C API 的 major 版本不兼容时显式拒绝，避免静默 ABI 错配 | P0 |
| CTL-5 | 所有变更操作同步返回：`accepted/rejected`、校验结果、operation ID（如有异步阶段）、当前图/参数版本 | P0 |
| CTL-6 | 异步操作支持查询与事件订阅：状态至少为 `accepted/running/succeeded/failed/cancelled`；排空删除、so 卸载、预热等必须有最终结果 | P0 |
| CTL-7 | 引擎不监听或自动应用本地配置文件变更；外部系统负责读取、审核、提交 JSON | P0 |

### 2.2 控制操作的一致性

- 创建图：完成 JSON 解析、Schema 校验、资源准入后才返回 `accepted`。
- 图变更：遵循既有事务语义；同步阶段完成校验与提交，排空等后置资源回收通过 operation ID 追踪。
- Node 参数热更新：遵循 `07-场景-动态修改Node参数.md`，下一 Packet 生效、同 Node 内原子、同 Node 串行。
- 控制 API 的调用不得阻塞数据面热路径。

## 3. 资源准入与共享池

### 3.1 决策

首期采用**共享资源池 + 容量检查**：所有会话共享 CPU、主存、GPU 与编解码资源；无租户配额、无会话硬配额、无优先级、无运行中抢占。

### 3.2 功能需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| RES-1 | 在创建图、动态新增档位/成员、加载模型/算子实例前执行资源准入检查 | P0 |
| RES-2 | 准入至少检查：GPU 显存及计算容量、NVDEC/NVENC 解码编码会话容量、CPU 线程与主存、边队列缓冲预算 | P0 |
| RES-3 | 资源不足时拒绝新请求；已运行图与会话继续运行，不抢占、不自动降级、不修改既有参数 | P0 |
| RES-4 | 拒绝结果必须包含资源类别、请求量、可用量、已用量、建议重试条件 | P0 |
| RES-5 | 节点/算子元数据声明资源估算（显存、编码/解码会话、CPU/主存、队列缓冲）；复杂算子可在预热阶段报告实际占用并二次准入 | P0 |
| RES-6 | 资源在会话/节点/so 卸载、档位删除完成后归还共享池；归还事件可观测 | P0 |
| RES-7 | 提供全局与按图/会话的资源水位查询：显存、编解码句柄、CPU/主存、队列缓冲 | P0 |
| RES-8 | 首期不提供优先级、租户账单、资源抢占与自动降级；后续能力不得破坏 RES-3 的默认语义 | P1 |

## 4. 故障恢复与升级

### 4.1 节点与会话故障

| 编号 | 需求 | 优先级 |
|---|---|---|
| REL-1 | 节点失败按图配置重试/重建；重试次数与退避时间可配置 | P0 |
| REL-2 | 节点持续失败超过阈值后停止**该会话**，释放其资源并发出终态事件；其他会话不受影响 | P0 |
| REL-3 | 节点失败事件包含错误码、重试次数、最终策略、受影响节点/分支/会话 | P0 |
| REL-4 | 不允许默认静默忽略持续失败；"尽力继续"只能由节点/图显式配置且输出必须携带降级/错误标记 | P1 |

### 4.2 进程故障与引擎升级

| 编号 | 需求 | 优先级 |
|---|---|---|
| REL-5 | 引擎进程崩溃由宿主或外部编排系统监控并重启；引擎不内置守护子进程 | P0 |
| REL-6 | 重启后外部控制系统以保存的完整 JSON 图定义重建会话；引擎保证重建操作可重复、幂等失败可诊断 | P0 |
| REL-7 | 引擎二进制升级采用停止/重启升级；升级前由外部停止或迁移会话，升级后外部重建 | P0 |
| REL-8 | 独立算子 so 升级遵循 `05-场景-算子so集成.md`：加载新版、灰度图变更、收尾旧版，不要求引擎重启 | P0 |

## 5. 权限与审计

| 编号 | 需求 | 优先级 |
|---|---|---|
| AUD-1 | 引擎不实现账户、身份认证与 RBAC；宿主完成鉴权后通过调用上下文提供不可空的 `caller_id` 与可选 `request_id` | P0 |
| AUD-2 | 所有控制操作写审计记录：调用来源、请求 ID、操作类型、目标图/会话/节点/so、请求摘要、结果、错误、操作 ID、时间戳 | P0 |
| AUD-3 | 审计覆盖创建/停止/销毁、图变更、参数修改、so 加载卸载、资源准入拒绝、节点失败与重试 | P0 |
| AUD-4 | 审计记录不得包含密钥、完整输入 URL 中的敏感查询参数或大体积业务 payload；采用脱敏/摘要 | P0 |
| AUD-5 | 支持按 request ID、caller ID、图/会话/节点、时间范围查询审计记录 | P1 |

## 6. 全局 SLA

| 编号 | 目标 | 验收口径 |
|---|---|---|
| SLA-1 | 实时链路端到端延迟 P99 ≤ 500ms | 输入接收时间到输出发送时间；适用拉流/解码→处理→编码/推流链路；合批等待、对齐窗口均计入 |
| SLA-2 | 单机稳定性 7×24 | 数据中心 GPU（T4/A10/L4 级）环境，目标负载持续运行；无死锁、进程崩溃、内存/显存/句柄单调增长 |
| SLA-3 | 会话故障隔离 | 单会话停止/失败/资源准入失败不影响其他会话输出帧连续性 |
| SLA-4 | 控制面不扰动数据面 | 图变更、参数更新、事件订阅与审计不造成未受影响分支丢帧或额外暂停 |

## 7. 统一验收矩阵

| 域 | 必过功能 | 性能/稳定性证据 |
|---|---|---|
| 基础图运行 | JSON 构图、校验、C++/C API 等价、透明自定义数据端到端传递 | 10 节点图框架开销符合 01 NFR-P-1/2；24h 无内存泄漏 |
| 动态转码 | 增删档、排空/快速删、码率热更、codec 切换、FLV+MP4 尾数据 | 既有档零丢帧；音画 ≤40ms；codec 切换不可播 ≤500ms |
| 多路合成 | 4-16 路进出、严格对齐、冻结→占位、自动/手动/热调布局 | 1080p30、单数据中心 GPU；既有画面零中断；成员风暴 24h |
| so 集成 | 目录/元数据/ABI 校验、多版本、灰度、逻辑/真卸载 | 升级后 24h 无延迟崩溃；加载卸载零数据面影响 |
| 异步推理 | Completion Queue、保序/缺口标记、同卡跨会话合批、热更新收尾 | 默认 10ms 合批；单卡路数较逐路 ≥3×；实时会话可关闭合批 |
| Node 参数 | 下一 Packet 生效、同 Node 原子、串行、拒绝不支持项 | 1,000 次连续变更无版本错配/泄漏 |
| 运行期事件 | 关键帧绑定格式事件、节点能力响应、旁路观察、上游控制 | 观察订阅阻塞不影响数据面；未受影响分支零丢帧 |
| 资源与恢复 | GPU/编解码/CPU/内存准入；不足拒绝；节点重试后停止会话；外部重建 | 资源归还可复用；故障会话与其他会话隔离；重建幂等 |
| 审计 | 调用来源、控制操作、错误、敏感字段脱敏 | 按 request/caller/图查询可追溯 |

### 7.1 自动化与环境级验收边界

`ctest` 默认 `ge_soak` 仅运行 20s，定位为冒烟，不可作为 24h/7×24 证据。以下项必须由发布负责人在目标数据中心 GPU 环境执行并归档报告：基础图 24h 内存泄漏、多路合成成员风暴 24h、so 升级后 24h 无延迟崩溃，以及 SLA-2 单机 7×24。执行命令为 `ge_soak --duration 24h`；多路合成风暴须额外使用 4–16 路场景。责任人：发布负责人；未附报告不得宣称通过环境级验收。

## 8. 需求冻结结论

首期范围为：单机、数据中心 GPU、嵌入式 C++/C 图引擎；JSON 外部控制；共享资源池容量准入；宿主鉴权、引擎审计；引擎重启升级、so 热升级；实时链路 P99 ≤500ms；单机 7×24 稳定性。

以下能力明确不在首期：gRPC/REST/Python SDK、本地配置热监听、引擎内置 RBAC、引擎二进制热升级、跨机分布式图、租户配额/优先级/抢占/自动降级、消费级 GPU 兼容承诺、HLS 排空收尾、AI/设备运行期事件。
