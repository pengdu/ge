# 图引擎实现计划与开发任务

> 依据 `00-需求规格说明书.md`、`02-架构设计.md`、`12-详细设计.md`、`13-接口与类设计.md`、`14-JSON-Schema设计.md`。每阶段完成后必须通过对应验收，再进入下一阶段。

## 1. 实施原则

- 核心库优先：先建立无插件、无 CUDA 的可验证最小运行时，再叠加异构、插件和业务算子。
- 先控制面正确性，再优化数据面性能；每个阶段保留性能基准，避免后续回归。
- 所有公开 C ABI 在生成骨架前以 `13-接口与类设计.md` 为准；任何不兼容变更必须更新 ABI major。
- 每个 Mutation/异步/插件阶段都必须包含失败与资源泄漏测试。

## 2. 阶段与依赖

```text
P0 基础契约与构建
 ├─ P1 GraphSpec/Schema/校验/能力协商
 ├─ P2 Packet/Buffer/Edge/同步调度
 │   └─ P3 Session/Mutation/连续链/分支操作
 ├─ P4 C ABI/PluginRegistry/逻辑卸载
 │   └─ P5 异步 Completion/Batcher
 ├─ P6 媒体基础算子与转码场景
 ├─ P7 合成场景与格式事件
 └─ P8 资源、观测、稳定性与验收
```

P1 与 P2 可并行；P4 可在 P2 完成公开 Packet ABI 后并行推进；P6/P7 依赖 P3/P4；P5 依赖 P4。

## 3. P0：基础契约与构建系统

### 目标

建立可编译、可测试的 C++20 工程骨架与稳定公开头文件，不实现业务算子。

### 任务

1. 创建 CMake 工程、模块 target、编译告警与 sanitizers 配置。
2. 创建 `include/ge/c/`、`include/ge/cpp/` 的公开目录，按 `13-接口与类设计.md` 生成空实现/声明。
3. 定义基础 ID、`Status/ErrorDetail`、版本头、opaque handle、内存所有权约定。
4. 建立单元测试、集成测试、性能基准的目录和 CTest 集成。
5. 增加 ABI 静态检查：C 头可被 C11 与 C++20 编译单元分别包含。

### 验收

- Linux x86_64 下 C++20 构建通过。
- C 头不依赖 C++ 类型；C/C++ 双编译验证通过。
- `ge_struct_header`、错误码、公开符号命名全部符合接口设计。

## 4. P1：GraphSpec、JSON Schema、校验与能力协商

### 目标

可解析、校验并导出 GraphSpec；可对 Node/Edge 做能力协商，生成确定性 ConnectionContract。

### 任务

1. 创建正式 JSON Schema：GraphSpec、MutationPatch、PluginManifest、CapabilityDescriptor。
2. 实现 JSON Parser/Serializer 与 `schema_version/$id` 规则；默认拒绝未知字段。
3. 实现 `GraphSpec`、`NodeSpec`、`EdgeSpec`、外部稳定 Node ID 与内部 NodeId 映射。
4. 实现 GraphValidator：端口存在、方向、必需输入、环、反馈边、外部 ID 唯一、共享依赖识别。
5. 实现 CapabilityDescriptor 与 `CapabilityNegotiator`：单 Edge 求交集、扇出公共交集、确定性选择、Conflict 详情。
6. 实现透明自定义类型标签精确匹配。
7. 实现 GraphBuilder 与 Mutation JSON 到候选 GraphSpec 的纯数据变换。

### 验收

- JSON GraphSpec/patch 往返序列化结果稳定。
- NV12→NV12 协商成功；P010→仅 NV12 失败并含 Convert 建议。
- 透明类型 `biz.UserProfile@v1` 精确匹配，v1→v2 拒绝。
- 扇出公共交集结果与下游声明顺序无关。
- 100 Node/300 Edge 图协商+校验 <50ms。

## 5. P2：Packet、Buffer、Edge 与基础调度

### 目标

实现无插件的进程内数据面：Packet、BufferPool、独立 Edge 队列、扇出和数据驱动 CPU 调度。

### 任务

1. 实现 Buffer/BufferRef、Host 内存池与 payload 引用计数。
2. 实现 Packet、Metadata 小对象优化和内置 type tag 注册。
3. 实现 SPSC EdgeChannel、容量、drop_oldest/drop_newest/block 语义与指标。
4. 实现 RouteTable、PacketRouter 与零拷贝扇出。
5. 实现 NodeRuntime 抽象和内置测试 Node（Source、PassThrough、Sink、Tee）。
6. 实现 Scheduler、CPU Executor、Ready 状态机、单并发/多并发 Node。
7. 实现 InputBinding 的 any/latest/aligned 基础策略。
8. 实现 EOS、Flush、Stop 最小生命周期。

### 验收

- 10 Node 线性图框架附加延迟 <50µs；单 Node 调度开销 <2µs。
- 扇出 Edge 各自队列独立；慢分支不修改快分支已消费 Packet。
- aligned/latest/any 的输入选择符合详细设计。
- TSAN/ASAN 下无数据竞争与泄漏。

## 6. P3：Session、Mutation 与拓扑版本

### 目标

实现不可变 RuntimeTopology、Session 生命周期、候选拓扑构建、原子发布、Drain/Fast 收尾。

### 任务

1. 实现 `RuntimeTopology`、`Session.current_topology` 原子读取与 `RetiredTopologyList`。
2. 实现 `MutationCoordinator`、MutationQueue、OperationRegistry 与状态机。
3. 接入 P1 Validator/Negotiator，接入 P2 Node/Edge 创建。
4. 实现 Add/Remove Node、Add/Remove Edge、`insert_chain`。
5. 实现 `remove_chain`：disconnect 与唯一外部输入/输出的 bypass。
6. 实现 `replace_node`：端口映射、参数迁移、预热、旧 Node 收尾。
7. 实现 `remove_branch`：共享依赖检测、专属分支 Drain/Fast。
8. 实现 Node ParameterSnapshot：下一 Packet 生效、同 Node 原子、同 Node 串行。
9. 实现 dry-run、版本冲突与操作查询。

### 验收

- 连续插入链不会出现半插入状态。
- 连续删除链 bypass 后旧在途 Packet 走旧链，新 Packet 走新 Edge。
- 共享 Node/Edge 删除被拒并返回依赖清单。
- 预热/协商/准入失败时旧图不变。
- 参数更新 N 用旧值、N+1 用新值；1000 次连续更新无版本错配。

## 7. P4：稳定 C ABI 与 PluginRegistry

### 目标

将 Node Runtime 接到独立 so；实现裸 so + manifest、C ABI、版本解析与默认逻辑卸载。

### 任务

1. 生成 `ge_abi.h`、`ge_plugin.h`、`ge_engine.h`、C++ 包装头。
2. 实现 HostApiAdapter：buffer、emit、event、log 接口。
3. 实现 PluginManifest 校验链、白名单路径、动态库加载和 descriptor 一致性检查。
4. 按 `type@version` 注册 Capability 与 operator vtable。
5. 实现插件实例创建、open/process/close/destroy 适配。
6. 实现 PluginLease 与逻辑卸载状态机。
7. 实现一键联动替换：按 Session 执行 ReplaceNode Mutation、汇总结果、全成功后逻辑卸载。
8. 创建示例插件与 ABI CI 对拍测试工具。

### 验收

- ABI major、manifest、依赖、符号不匹配均被拒绝且不影响已加载插件。
- 两个 type@version 并存并可被不同 Session 使用。
- 默认逻辑卸载后无法新建 Node，旧引用归零后资源释放；不执行 dlclose。
- 一键联动替换产生逐 Session 聚合结果，无跨会话回滚。

## 8. P5：异步推理、Completion Queue 与 Batcher

### 目标

实现回调式异步 Node、Completion Queue、拓扑/参数版本隔离、同卡跨会话 batch。

### 任务

1. 实现 `ge_operator_submit`、CompletionSink、CompletionQueue。
2. 实现 AsyncRuntime：请求表、孤儿结果检测、ReorderBuffer、timeout 缺口标记。
3. 实现 Batcher key：type@version、模型、device_id、parameter_version。
4. 实现最大 batch/10ms 超时 flush；会话/Node/全局关闭合批。
5. 实现 GPU Executor submit 模型（初期可用 fake async backend 测试）。
6. 实现 Stop/Flush/Mutation 下的在途等待、超时丢弃与 no orphan 保证。
7. 实现异步指标：在途、batch 分布、等待、P50/P99、缺口、孤儿。

### 验收

- Submit 不阻塞 CPU Executor；Completion 不直接进入图回调。
- 乱序完成被保序；超时缺口有 dropped/timeout 标记。
- 不同 topology/parameter 版本不会混 batch，也不会错误交付。
- 同卡 batch 测试达到单卡路数≥3×基线（目标模型/硬件）。

## 9. P6：媒体基础算子与动态转码

### 目标

接入 FFmpeg/NVDEC/NVENC（目标环境），实现动态转码档位的端到端主链路。

### 任务

1. 实现媒体 Source/Demux/Decode、Scale、ColorConvert、Encode、Mux/Sink 算子。
2. 实现媒体 CapabilityDescriptor、GPU Device Buffer 与零拷贝路径。
3. 实现 Rendition 子图模板与转码控制封装。
4. 实现新增档位预热、强制 IDR、音画时间戳对齐。
5. 实现 Drain 删除：EOS、封装尾数据、2s 超时升级 Fast。
6. 实现码率/GOP/水印热更新与 codec 替换 Node 流程。
7. 实现 FLV/MP4 结果验收工具链。

### 验收

- 新档位首帧 IDR，音画偏差≤40ms。
- 新增/删除期间既有档位零丢帧、无花屏。
- codec 切换不可播窗口≤500ms。
- Drain 后 FLV/MP4 完整可播，资源<100ms 可复用。

## 10. P7：多路合成、格式事件与混音边界

### 目标

实现 4–16 路视频合成、严格对齐、成员动态进出、布局热调与关键帧格式事件。

### 任务

1. 实现 Mix/Compositor Node：自动网格、手动布局、z-order、cover/contain、占位层。
2. 接入 aligned 输入策略：窗口、冻结/黑帧/占位/跳过、冻结超时升级占位。
3. 实现成员加入/退出的输入分支 Mutation 与布局参数热更新。
4. 实现音视频独立进出与基础混音 Node 接口（静音/增益热更）。
5. 实现 DataPlaneEvent、MediaFormatChanged、关键帧前置传播与 Node 响应。
6. 实现旁路观察订阅：每 subscription 有界队列，同订阅串行、跨订阅并行。

### 验收

- 4–16 路 1080p30；加入不影响既有画面。
- 20–100ms 对齐、抖动输入下输出稳定。
- 冻结→占位、重连恢复、布局下一帧生效无撕裂。
- 格式变化事件先于关键帧；慢观察者不影响数据面。

## 11. P8：资源、可靠性、观测与发布验收

### 目标

完成共享资源池、故障隔离、审计、Prometheus 指标与 7×24 稳定性验收。

### 任务

1. 实现 GPU/编解码/CPU/主存/Edge Buffer 资源账本、Reserve/Commit/Release。
2. 接入 Node 资源估算和预热实际资源修正。
3. 实现 Node 重试/重建、超过阈值停止 Session、外部重建友好错误。
4. 实现 caller_id/request_id 审计及敏感 URL/密钥脱敏。
5. 实现 Prometheus/进程内指标导出、健康检查和看门狗。
6. 建立场景验收自动化、故障注入、性能基准与 7×24 soak 测试。

### 验收

- 资源不足拒绝新请求，既有会话持续运行。
- 会话故障隔离，资源可观测归还。
- SRS 统一验收矩阵全部通过。
- 目标负载 7×24 无死锁、崩溃、内存/显存/句柄单调增长。

## 12. 测试策略

| 层级 | 内容 |
|---|---|
| 单元测试 | Schema、协商、队列、同步、参数版本、状态机、资源账本、错误映射 |
| 属性测试 | 协商确定性、扇出顺序无关、Mutation 失败不改变旧拓扑、序号单调性 |
| 集成测试 | so 生命周期、连续链 Mutation、异步 Completion、转码、合成、格式事件 |
| 故障注入 | 预热失败、资源不足、CDN 失败、插件 ABI 错、Completion 迟到、Drain 超时、慢订阅者 |
| 性能测试 | 调度开销、协商耗时、Mutation 生效、batch 吞吐、端到端 P99 |
| Soak 测试 | 24h 变更风暴、成员进出、插件升级、资源反复申请/释放 |
| 争用压测 | 同一 gtest 二进制 N 路并发 × repeat × rounds，让执行器线程饿 CPU；只在这种条件下暴露的活性缺陷（丢失唤醒、park/retry 竞争）在单进程 ctest 里 0/90 不复现 |

### 12.1 争用压测（label `stress`）

- 入口：`tests/stress/run_stress.sh <bin> [parallel] [repeat] [rounds] [timeout-s] [filter]`，每个副本带看门狗，超时按挂死计失败并 `kill -KILL`，输出尾 40 行日志。
- CMake：`ge_add_stress_test(<unit-target> [gtest-filter])` 注册为 `<unit-target>_stress`，label `stress`、`RUN_SERIAL`；参数由 cache 变量 `GE_STRESS_PARALLEL/REPEAT/ROUNDS/TIMEOUT` 控制（默认 8/10/3/600）。
- 覆盖：`ge_scheduler_test`、`ge_mutation_stress_test`、`ge_async_runtime_test`、`ge_session_test`、`ge_flow_limiter_test`、`ge_onnx_infer_test`（仅 E2E 用例）。
- 约定：常规 `ctest -LE stress`；夜间 / 合并前在 asan 与 tsan 树各跑一次 `ctest -L stress`。新增涉及 `Scheduler`、`EdgeChannel`、`AsyncRuntime` 的改动必须附 asan stress 通过记录。
- 已由此机制定位并修复：`Invoke` 门槛 5/6 的丢失唤醒（docs/16 §3）。
- 测试判定约定（Linux 首次 stress 暴露）：断言"暂停后不再有包到达"不得用"sink 计数 N ms 内不变"猜时序——8 副本争用下调度线程可被饿死 >20ms。统一用 `tests/unit/test_operators.h` 的 `WaitDrained(topo)`：按拓扑序检查每个节点 `quiescent()` 且其输出边 `empty()`，连续 3 趟成立才算静止（包只能跑在扫描前面，跑在前面即已到 sink）。`run_stress.sh` 导出 `GE_STRESS=1`，PERF-1 预算（`TenNodeLatencyAndSchedulingOverhead`）在该环境下只记录 `RecordProperty` 不断言。
- TSan stress 追加约定：① 需要"节点卡在 Process 里"的用例（drain 超时升级 fast）用 `Gate` 算子（`test_operators.h`，`Release()`/`Close()` 放行）而不是 `delay_us` 睡眠——8 副本 TSan 下 2ms 睡眠常常 30ms 内就排空，超时不触发；② `ge_scheduler_test` 的 stress 注册过滤掉 `TenNodeLatency*`（inline 执行器，争用对它无意义，TSan 下每次 ~15s × 10 repeat 直接撞看门狗）；③ OnnxInfer "确实合批"用例的 `batch_timeout` 在 `GE_STRESS` 下放宽到 500ms（20ms 窗口内要送达第二个请求，是调度时序假设，不是合批逻辑）。

### 12.2 CI（GitHub Actions，`.github/workflows/ci.yml`）

- 入口统一为 `ci/build.sh <release|asan|tsan> <regular|stress>`；Linux 依赖由 `ci/setup-ubuntu.sh` 安装（apt FFmpeg 6.1、ORT 官方 CPU tarball + 手写 `libonnxruntime.pc`），`ci/Dockerfile.ci` 复用同一脚本供本地复现。
- push/PR：ubuntu-24.04 GCC release/asan/tsan、Clang release、macos-15 release，各跑 `ctest -LE stress`。
- 夜间 02:17（Asia/Shanghai）及 `workflow_dispatch(stress=true)`：Linux GCC release/tsan 跑 `ctest -L stress`，日志作为 artifact 上传。
- 编译器差异约定：`ge_build_flags` 里 C++ 专属警告用 `$<COMPILE_LANGUAGE:CXX>` 限定；测试目标额外关 `-Wno-missing-field-initializers`（GCC/clang≤18 对指定初始化省略字段告警）与 GCC `-Wno-maybe-uninitialized`（`std::variant` 析构器误报）；`src/` 不得依赖这两项豁免。FFmpeg `av_warn_unused_result` 在 GCC 下 `(void)` 无效，必须消费返回值。
- `std::atomic_load/store(shared_ptr*)` 在 libstdc++ C++20 已 deprecated 而 libc++ 无 `std::atomic<shared_ptr>`，统一用 `include/ge/cpp/atomic_shared_ptr.h`。

## 13. 建议首个可运行里程碑

完成 P0 + P1 + P2 + P3 后交付：

- JSON 构图、能力协商与扇出；
- 内置测试 Node 的数据驱动执行；
- Session 内连续 Node 链插入/删除/bypass、替换、分支删除；
- 参数下一 Packet 生效；
- 不依赖 GPU/插件即可完整验证拓扑动态性。

这是一条最小、可测试、可演示的核心引擎闭环。
